# 模拟用户行为数据方案

## 目标

基于 `data/bilibili_10w_pro.csv` 生成约 20000 名用户，以及点击、观看、完播、点赞、收藏、投币、分享等行为数据。生成结果需要满足两个目标：

- 看起来接近真实短视频平台行为：兴趣偏好、长尾活跃度、互动漏斗、热度衰减。
- 能支撑 F3-F7：相似用户、视频推荐、热度预测、视频聚类、用户聚类都能得到稳定、可解释的结果。

## 推荐参数

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 用户数 `U` | 20000 | 高于课程要求的 10000。 |
| 视频数 `V` | 使用 CSV 全量 | 当前已有 10 万级视频。 |
| 主题数 `K` | 12 或 16 | 比 10 稍细，便于分出更多兴趣群体。 |
| 用户群体数 `M` | 与 K 相同或略多 | 可设置为 12 或 16。 |
| 行为总量 | 150 万到 300 万 | 足够分析，又不至于文件过大。 |
| 单用户行为数 | 低活 20-80，中活 80-250，高活 250-1000 | 体现长尾活跃度。 |
| 时间粒度 | 天或小时 | F5 初版建议按天预测。 |

## 第一步：视频建模

### 1.1 分类和标签编号

读取每个视频的 `category` 和 `tag`，建立：

```text
categoryName -> categoryId
tagName -> tagId
tagId -> videoIds
```

这样做的原因是：字符串不适合频繁计算，把分类和标签压缩成整数编号后，既节省空间，也方便建立倒排索引。

### 1.2 标签清洗与兴趣分类

CSV 中可直接使用的字段主要是 `category`、`tag` 和 `title`。推荐按下面流程处理：

1. **分类清洗**
   - 去掉首尾空格。
   - 空分类统一为 `unknown-category`。
   - 原始分类保留在 `category_name`，同时映射为整数 `category_id`。

2. **标签拆分**
   - `tag` 字段可能使用 `,`、`，`、`;`、`；`、`/`、`|` 等分隔符。
   - 拆分后去掉空白项。
   - 过短标签、纯符号标签、明显无意义标签可以忽略。
   - 如果拆分后没有有效标签，则补一个 `category:<category_name>` 伪标签，避免视频没有标签维度。

3. **标签频率统计**
   - 第一遍读取 CSV 时统计每个标签出现次数。
   - 第二遍建模时，低于阈值的标签归为 `rare-tag` 或只保留较低权重。
   - 建议阈值：小样本调试用 1，全量数据用 3 或 5。

4. **兴趣主题映射**
   - 优先使用 `category` 映射主主题。
   - 使用 `tag` 命中关键词时，对对应主题加权。
   - 使用 `title` 命中关键词时，给较小修正权重。

推荐先定义 12 个可解释兴趣主题：

| 主题编号 | 主题名 | 典型分类或关键词 |
| --- | --- | --- |
| 0 | 内容创作与素材 | 素材、剪辑、影视、短片、动画、绿幕 |
| 1 | 数码硬件与极客 | 数码、电脑、NAS、硬盘、装机、评测 |
| 2 | AI 与软件工具 | AI、软件、工具、教程、自动化、办公 |
| 3 | 游戏娱乐 | 游戏、手游、主机、攻略、实况 |
| 4 | 生活日常 | 日常、vlog、生活、情感、校园 |
| 5 | 美食与手作 | 美食、烹饪、制作、手工 |
| 6 | 知识学习 | 科普、学习、课程、考试、知识 |
| 7 | 音乐舞蹈 | 音乐、舞蹈、翻唱、演奏 |
| 8 | 动漫二创 | 动画、番剧、二创、鬼畜、MMD |
| 9 | 体育汽车 | 运动、健身、汽车、赛事 |
| 10 | 旅行户外 | 旅行、户外、摄影、风景 |
| 11 | 泛娱乐热点 | 搞笑、娱乐、明星、热点、萌宠 |

为什么要这样处理：

- `category` 稳定但粒度粗，适合作为主主题。
- `tag` 粒度细但噪声多，适合作为主题修正和倒排索引。
- `title` 信息丰富但更容易标题党，因此只给较低权重。
- 保留 `category_id`、`tag_ids`、`topic_id` 和 `topic_vector`，后续 F3-F7 可以复用同一套基础表示。

### 1.3 主题向量

每个视频生成一个长度为 K 的 `topic_vector`。

简单可解释做法：

1. 根据 `category` 映射到主主题，给该维度增加 0.60。
2. 根据有效 `tag` 命中主题关键词，每次给对应维度增加 0.20。
3. 根据 `title` 命中主题关键词，每次给对应维度增加 0.08。
4. 如果没有任何命中，则使用 `hash(category) % K` 生成兜底主题。
5. 对向量归一化，使所有维度之和为 1。

示例：

```text
数码 + NAS + 硬盘 -> 硬件折腾主题权重大
AI + 工具 + 教程 -> AI 应用主题权重大
影视剪辑 + 素材 -> 内容创作主题权重大
```

不直接调用聚类库的原因是：课程要展示算法原理。初版可以用规则生成主题，后续如果需要更像“聚类”，可以自实现 KMeans 对视频向量再聚一次。

### 1.4 视频质量分

质量分用于控制基础曝光。建议使用播放量和互动率的组合：

```text
quality_score =
    0.45 * normalized_log_view
  + 0.20 * smoothed_like_rate
  + 0.15 * smoothed_favorite_rate
  + 0.15 * smoothed_coin_rate
  + 0.05 * smoothed_share_rate
```

其中：

```text
smoothed_rate = action_count / (view_count + 100)
```

为什么要这样做：

- `log(1 + view_count)` 避免头部视频播放量过大，压扁其他视频。
- 平滑分母避免低播放视频互动率虚高。
- 投币、收藏比点赞更稀缺，所以可以给较高权重。

## 第二步：用户建模

### 2.1 用户兴趣群体

生成 20000 名用户，每个用户分配一个 `group_id`。每个群体对应一个主兴趣主题，但允许混合兴趣。

用户兴趣向量建议：

```text
primary_topic: 0.55 - 0.75
secondary_topic: 0.15 - 0.30
other_topics: share remaining weight
```

这样生成的用户既有清晰偏好，又不会过于机械。

### 2.2 活跃度分布

使用长尾分布模拟平台用户：

| 用户类型 | 占比 | 行为数范围 |
| --- | --- | --- |
| 低活用户 | 70% | 20-80 |
| 中活用户 | 25% | 80-250 |
| 高活用户 | 5% | 250-1000 |

为什么要这样做：

真实平台中少量高活用户贡献大量行为。如果每个用户行为数一样，用户聚类和相似用户分析会显得不真实。

## 第三步：候选视频召回与点击生成

不要让每个用户遍历全部视频。推荐流程是：

1. 根据用户主兴趣和次兴趣找到对应主题的视频池。
2. 从视频池中随机抽取一批候选，例如 100-300 个。
3. 对候选视频计算点击倾向分。
4. 按分数采样或排序，生成一次点击行为。

点击倾向分：

```text
click_score =
    0.65 * dot(user_interest_vector, video_topic_vector)
  + 0.25 * quality_score
  + 0.10 * freshness_score
  + random_noise
```

其中 `freshness_score` 根据发布时间衰减，近期视频略有加成。

## 第四步：行为漏斗模拟

一次点击发生后，再继续生成后续行为。

### 4.1 观看时长

观看比例由兴趣匹配度决定：

| 匹配情况 | 观看比例 |
| --- | --- |
| 高匹配 | 均值约 0.75-0.95 |
| 中匹配 | 均值约 0.40-0.70 |
| 低匹配 | 均值约 0.05-0.30 |

实现时可以不用复杂分布库，直接用均匀随机数加扰动：

```text
watch_ratio = base_ratio + noise
watch_sec = min(duration_sec, duration_sec * watch_ratio)
```

### 4.2 强反馈行为

强反馈必须依赖观看比例：

```text
if watch_ratio < 0.30:
    like/favorite/coin/share 概率很低
if 0.30 <= watch_ratio < 0.70:
    like 有一定概率，favorite/coin/share 较低
if watch_ratio >= 0.70:
    like/favorite/coin/share 概率明显提高
```

概率可以被视频真实互动率动态缩放：

```text
like_prob = base_like_prob * (0.5 + real_like_rate_factor) * match_factor
coin_prob = base_coin_prob * (0.5 + real_coin_rate_factor) * match_factor
```

建议基础概率：

| 行为 | 基础概率 |
| --- | --- |
| 点赞 | 3%-12% |
| 收藏 | 1%-6% |
| 投币 | 0.5%-4% |
| 分享 | 0.2%-2% |

## 第五步：时间序列注入

每个行为时间戳必须满足：

```text
event_timestamp >= video_publish_timestamp
```

推荐使用“发布后天数 offset”的方式生成：

1. 大多数观看发生在发布后早期。
2. 随时间逐渐衰减。
3. 少量高质量视频有二次爆发。

不用复杂分布库时，可以自实现离散衰减采样：

```text
day_offset = sample from weighted days
weight(day) = exp(-lambda * day)
```

二次爆发：

```text
if quality_score is high and random_hit:
    day_offset += burst_center + random(-burst_width, burst_width)
```

这样做可以让 F5 的热度预测看到明显趋势，而不是完全均匀的时间序列。

## 生成数据如何支撑 F3-F7

| 功能 | 数据支撑 |
| --- | --- |
| F3 相似用户 | 用户兴趣向量和行为反馈分能计算用户相似度。 |
| F4 视频推荐 | 标签倒排索引、相似用户喜欢的视频、视频质量分可生成推荐。 |
| F5 热度预测 | 行为时间戳能按天统计观看量，并预测未来趋势。 |
| F6 视频聚类 | 视频受众向量记录哪些兴趣群体看过该视频。 |
| F7 用户聚类 | 用户兴趣向量可直接作为聚类输入。 |

## 建议输出规模检查

生成后至少输出这些统计：

- 视频总数。
- 用户总数。
- 行为总数。
- 人均行为数。
- 点赞率、收藏率、投币率、分享率。
- 每个兴趣群体的人数。
- 每个主题的视频数。
- 每天行为量分布。

这些统计既能验证模拟是否合理，也能直接放入课程报告。
